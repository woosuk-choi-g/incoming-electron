# ADR 0001: 타이머 완료 여부를 파생 상태로 계산한다

- 상태: 승인
- 결정일: 2026-08-28

## 배경

Timer Overlay는 renderer가 백그라운드에서 지연되거나 앱이 종료된 동안에도
시스템 시각을 기준으로 정확한 타이머 상태를 복구해야 한다. 여러 오버레이가
같은 타이머를 표시하므로 각 창이 별도로 완료 상태를 저장하면 상태가 서로
어긋날 수 있다.

## 결정

영속 가능한 `TimerState`는 `paused`와 `running`만 사용한다. `expired`는
`running.expiryTime <= now`일 때 계산되는 `TimerStatus`로 표현하며 저장하지
않는다.

- `paused`: 남은 시간을 저장한다.
- `running`: 시작 시각과 만료 시각을 저장한다.
- `expired`: 현재 시각과 만료 시각을 비교해 계산한다.
- 1회성 타이머는 만료된 `running` 상태를 유지한다.
- 반복 타이머는 기존 만료 시각을 기준으로 다음 주기를 계산해 지연으로 인한
  드리프트를 누적하지 않는다.

완료 알림을 정확히 한 번 전달해야 할 때는 완료 상태를 추가하지 않고 세션 ID
또는 마지막으로 알린 주기처럼 이벤트 전달 전용 정보를 별도로 관리한다.

## 결과

장점:

- 시스템 시각이 완료 여부의 단일 진실 공급원이 된다.
- 앱 재실행과 renderer 지연 후 별도 완료 전이 없이 상태를 복구할 수 있다.
- 다중 창 사이에서 저장 상태와 실제 시간의 불일치를 줄인다.
- 저장 스키마와 상태 전이 조합이 단순해진다.

트레이드오프:

- 실행 중과 만료됨을 구분할 때 항상 현재 시각이 필요하다.
- 만료된 타이머의 일시정지처럼 허용되지 않는 전이를 명시적으로 차단해야 한다.
- 완료 알림의 중복 방지는 상태 모델 외부에서 처리해야 한다.
