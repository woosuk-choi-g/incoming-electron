# Timer Overlay 로드맵

## 제품 목표

게임 중 반복 이벤트를 놓치지 않도록 여러 타이머를 화면 위에 표시하고,
앱을 다시 실행해도 설정과 상태를 복구하는 Windows 데스크톱 앱을 만든다.

MVP에서는 다음 가치에 집중한다.

- 정확한 타이머 상태와 시간 계산
- 게임을 방해하지 않는 투명·항상 위 오버레이
- 안전한 renderer–preload–main IPC
- 로컬 우선 저장과 재실행 복구
- 설치 가능한 릴리스와 자동화된 품질 검증

웹, 모바일, 커뮤니티, 네이티브 DirectComposition 렌더러는 MVP 범위에서
제외한다.

## 운영 원칙

- 아래 표의 각 행은 PR 하나를 원칙으로 한다.
- PR은 레이어가 아니라 사용자가 확인할 수 있는 기능 단위로 완결한다.
- 각 PR에 정상 흐름 1개와 실패 또는 경계 흐름 1개 이상의 테스트를 추가한다.
- 기능 상태가 바뀌면 README와 로드맵을 같은 PR에서 갱신한다.
- 선행 PR이 필요한 경우 표의 순서를 따른다.

## 현재 기준선

### 구현됨

- React, TypeScript, Vite 기반 renderer
- Electron main/preload 및 타이머 gateway 구조
- 타이머 생성과 개별 오버레이 창 표시
- 시작, 일시정지, 재개, 초기화, 완료, 반복 상태 모델
- 제목과 시간이 반영되는 기본 카운트다운
- 시스템 트레이와 메인 창 복원
- 메모리 기반 timer repository와 JSON 저장 기반
- Playwright Electron E2E 테스트 골격

### 미완성 또는 보완 필요

- 앱 시작 시 저장된 타이머를 repository와 UI에 복구하지 않음
- 생성 시 저장되지 않으며 제거와 창 닫기 책임이 분리되어 있음
- 관리자 UI가 초기 목록 조회와 창 간 상태 갱신을 사용하지 않음
- 저장 파일 부재·손상과 비정상 종료 처리가 부족함
- 생성 폼이 제목, 반복, 알림 설정을 지원하지 않음
- 초기화, 완료, 반복 상태 전이가 UI 실행 제어와 연결되지 않음
- 일부 IPC가 `any`와 문자열 채널을 사용하며 입력 검증이 일관되지 않음
- README의 기능 및 기술 스택이 실제 구현과 일치하지 않음
- 단위·컴포넌트 테스트, CI, 접근성, 배포 검증이 부족함

### M1 종료 조건

- 사용자가 프리셋을 생성, 수정, 삭제, 실행할 수 있다.
- 타이머가 시작, 일시정지, 재개, 초기화, 완료, 반복된다.
- 시스템 시간 기준 계산으로 renderer 지연 후에도 시간이 복구된다.
- 앱 재실행 후 프리셋과 필요한 실행 상태가 복구된다.
- 핵심 상태 단위 테스트와 Electron E2E가 통과한다.
